V1-plan 

Keep it small so it actually gets built.

Frontend: React or Next.js.
Practice repos: JSON files (files, issues, comments, PRs, commits). No database.
Progress: localStorage. No accounts in v1.
Behavior tracking: just state in the browser (what was opened, what was picked). The quiz reads from this.
Real issue finder (later): GitHub Search API through a small backend proxy so the token isn't exposed and rate limits are handled.
Login (later, optional): GitHub OAuth.
Build plan
One complete practice repo and the explore screens.
Mission, health check, reproduce tab.
Issue pick with feedback.
Short quiz.
Results and tips.
Test with 5 to 10 students from our college and watch where they get stuck.
Terminal walkthrough and review simulation.
Repos 2 to 6.
Real issue finder.
Optional GitHub login.

Steps 1 to 5 are the first version.

Risks
Scope. We're building a trainer, not a GitHub clone. Anything that doesn't serve the lesson gets cut.
Content effort. Six repos with believable issues and comments is real writing work. Start with two.
Fake feels fake. If the repo isn't believable, people won't take it seriously. Real repos' issue threads are a good reference for tone.
Too much text. If basics run past 2 minutes, we lose people.
